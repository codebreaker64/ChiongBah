# Releasing an APK

The workflow `.github/workflows/android-apk.yml` builds a release APK on GitHub's machines. You do
not need Android Studio or a local Android SDK.

## What triggers it

| Trigger | What you get |
|---|---|
| Push a tag that starts with `v`, for example `v1.1.0` | A GitHub Release named after the tag, with `chiong-bah-1.1.0.apk` attached. Tags with a hyphen (`v1.1.0-beta.1`) are marked as pre-releases. |
| **Actions → Android APK → Run workflow** | The APK as a downloadable artifact on the run page. No release is created. |

Before building, the workflow runs `expo lint`, `tsc --noEmit` and the Jest tests. If any fail, no APK
is built.

Each build gets a `versionCode` of 100 plus the workflow's run number, so every new APK can update
the one before it. The `versionName` is the tag without the `v`.

## One-time set-up: an upload keystore

Without a keystore the workflow still works, but it signs with the public debug key and says so in
the run summary. That is fine for trying the app on your own phone. Set up a real key before you
share the APK, because Android refuses to update an app that was signed with a different key.

**1. Create the keystore** (PowerShell; `keytool` comes with any JDK, for example the one inside
Android Studio at `C:\Program Files\Android\Android Studio\jbr\bin`). Keep the file and passwords
somewhere safe, such as a password manager. If you lose them you cannot ship updates to people who
installed a build signed with this key.

```powershell
keytool -genkeypair -v -keystore chiongbah-upload.jks -alias chiongbah -keyalg RSA -keysize 2048 -validity 10000
```

**2. Copy it as base64** to the clipboard:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("chiongbah-upload.jks")) | Set-Clipboard
```

**3. Add four repository secrets** under **Settings → Secrets and variables → Actions → New
repository secret**:

| Secret | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | The base64 text from step 2 |
| `ANDROID_KEYSTORE_PASSWORD` | The keystore password |
| `ANDROID_KEY_ALIAS` | `chiongbah` (or the alias you chose) |
| `ANDROID_KEY_PASSWORD` | The key password (the same as the keystore password unless you set a different one) |

Never commit the `.jks` file. `.gitignore` already excludes `*.jks`.

## Cutting a release

```powershell
git tag v1.1.0
```

```powershell
git push origin v1.1.0
```

The release appears under **Releases** when the run finishes, usually in 15 to 25 minutes.

## How signing works

`android/` is generated by `expo prebuild` and is not in git. The config plugin
`plugins/withReleaseSigning.js` adds a release signing config to the generated
`android/app/build.gradle`. It reads the keystore from the `CHIONGBAH_UPLOAD_*` environment
variables, which the workflow fills from the secrets above, and it falls back to the debug key when
they are missing. `app.config.js` takes the version name and code from `APP_VERSION` and
`ANDROID_VERSION_CODE`.
